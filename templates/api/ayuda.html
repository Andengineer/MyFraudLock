Guía rápida

  • Pendiente — En espera de revisión por un analista.
  • Fraude confirmado — Validado como transacción fraudulenta.
  • Falso positivo — La transacción era legítima.

El sistema calcula un score de riesgo (0–100). A mayor score, mayor probabilidad de fraude.

El umbral actual es {{ config.umbral_score|default:70 }}%. Las transacciones con score ≥ umbral generan incidentes automáticamente.

El modelo DAFD-Net (Deep Learning con Embeddings) analiza: importe, marca de tarjeta, banco emisor, código ECI, región, categoría, dominio email, estado transacción, BIN, y 7 ratios financieros calculados (AAR, CMR, ASI, VRR, DAR, CSI, DPE). La explicación SHAP muestra los factores de mayor influencia.

Además de calcular el score, el sistema despliega el razonamiento de la red neuronal empleando SHAP (Valores de Shapley).

  • Reglas en Español: En lugar de lidiar con el código bruto, verás alertas claras como "Varias compras seguidas abortadas", logrando fácil visibilidad sin conocimientos de código.
  • Barras de Impacto: Las variables rojas empujan la predicción al lado de Bloqueo (Fraude), mientras que las verdes atenúan la sospecha.
  • Diccionario Nativo: Los ingenieros ya tradujeron los factores principales de previous_failed_attempts a "Múltiples Intentos Fallidos".

  • Individual: ingresa importe, marca de tarjeta, tipo, banco emisor, ECI, región, categoría, email dominio, estado transacción, BIN, etc. Usa los botones Caso Fraude y Caso Legítimo para auto-rellenar.
  • Por lote (CSV): sube un archivo con cabeceras mínimas: importe,card_brand,card_type,customer_region,product_category.
